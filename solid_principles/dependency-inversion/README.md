# Dependency Inversion Principle (DIP)

## Definition

The Dependency Inversion Principle is one of the five SOLID design principles.

It establishes two main rules:

1. High-level modules should not depend on low-level modules. Both should depend on abstractions.
2. Abstractions should not depend on details. Details should depend on abstractions.

## Main Idea

High-level modules should depend on abstractions instead of concrete implementations.

This reduces coupling and makes software easier to extend, maintain, and test.

## Key Points

- Depend on abstractions rather than concrete implementations.
- Reduce coupling between high-level and low-level modules.
- Use interfaces to define contracts.
- Allow different implementations to be interchangeable.
- Use Dependency Injection to provide dependencies from the outside.

## Important

Dependency Inversion Principle (DIP) is a design principle.

Dependency Injection (DI) is a technique used to provide dependencies to a class.

They are related, but they are not the same.
